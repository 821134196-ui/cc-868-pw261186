# 请求转发网关（区分计费 · 两级额度 · 按可观察消耗结算）

零依赖（Node ≥ 20 内置模块）。一个进程启动：

- **网关** `:8080` — 转发三类请求并按类别区分计费，每租户两级令牌桶
- **样例后端** `:9101/:9102/:9103` — 流式 / 轻量查询 / 慢请求
- **调试页** `http://127.0.0.1:8080/debug` — 实时额度水位、发请求、改参数、看结算事件

```bash
npm start          # 启动网关 + 样例后端
npm test           # 18 个单元 + 端到端结算测试
```

## 计费模型

| 类别 | 路由 | 费用 |
|---|---|---|
| 流式 | `GET /stream?chunks=N&interval=ms` | 准入费 + 每投递一个 NDJSON 块 |
| 轻量查询 | `GET /query` | 固定费用 |
| 慢请求 | `GET /slow?ms=4000` | 准入费 + 每 250ms 占用 tick |

每个租户两个令牌桶：**持续额度**（容量小、恢复快）先扣，**突发额度**（容量大、恢复慢）兜底。两桶都付不起 → `429` + `Retry-After`，不产生任何费用。请求在途期间额度耗尽 → 熔断（流式会收到 `{"gatewayError":"quota_exhausted"}` 终止帧）。

## 结算策略（按可观察的消耗）

| 终止方式 | 结算 |
|---|---|
| 正常完成 | 准入费 + 全部计量单位 |
| 客户端取消 | 已计量部分即消耗，结算即止 |
| 后端产出前拒绝（5xx / 连接失败） | **准入费全额退还**，净费用 ≈ 0 |
| 后端中途崩溃（`failAfter=K`） | 已观察到的 K 个块 + 准入费照计 |

租户标识：`?tenant=xxx` 或 `X-Tenant-Id` 头，缺省 `anon`。

## 调试页能做什么

1. **对比不同代价**：场景预设（均衡 / 低价流式 / 高价流式 / 浅突发 / 深突发）或手动改参数，点“应用”立即生效
2. **观察拒绝**：`×10 并发` 打满额度 → 看 `429`、中途熔断、事件日志中的拆账
3. **观察恢复**：水位曲线持续额度快速回升、突发额度缓慢爬升
4. **验证结算**：发一个慢请求然后点“取消”；或设 `failAfter=3` 让后端崩溃 → 事件日志给出 `净扣 / 退费 / 计量单位`

## 手动验证（curl）

```bash
curl "http://127.0.0.1:8080/stream?tenant=demo&chunks=5"          # 正常流式
curl "http://127.0.0.1:8080/stream?tenant=demo&reject=1"          # 后端拒绝 → 全额退
curl "http://127.0.0.1:8080/stream?tenant=demo&failAfter=3"       # 后端崩溃 → 计 3 块
curl --max-time 1 "http://127.0.0.1:8080/slow?tenant=demo&ms=5000" # 取消 → 按 tick 结算
curl "http://127.0.0.1:8080/api/state"                            # 额度/事件快照
```

## 管理 API

- `GET /api/state` — 全部租户水位、计数器、事件日志
- `POST /api/config` — `{"costs":{...},"quota":{...}}` 部分更新，或 `{"preset":"pricey-stream"}`
- `POST /api/reset` — 重置全部租户额度与事件

## 结构

```
src/config.js    默认代价/额度 + 场景预设
src/buckets.js   两级令牌桶（先持续后突发，按拆账退款）
src/meter.js     单请求计量器（扣费记录、退款、结算摘要）
src/gateway.js   转发 + 计量 + 熔断 + 管理 API
src/backends.js  三个样例后端（可模拟崩溃/拒绝）
public/debug.html 调试页
test/            node:test 单元 + 端到端结算测试
```

已知取舍：演示实现，状态全在内存；流式转发按行计量（末尾不足一行的产出也计为一个单位）；计量以网关观察到的上游产出为准。
